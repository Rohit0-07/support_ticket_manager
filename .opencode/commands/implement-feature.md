# Command: /implement-feature [feature-name]

Implements a feature by writing production code that makes the generated tests pass.

## Pre-Conditions (Validated Before Starting)

> [!IMPORTANT]
> Before writing any code, verify ALL of the following exist:
> 1. `features/<feature-name>/1_spec.md` — Must exist (but do NOT use it for implementation decisions)
> 2. `features/<feature-name>/2_tech_spec.md` — **Primary source** for architecture, interfaces, and contracts
> 3. `features/<feature-name>/tests/` — Tests must exist (generated via `/generate-tests`)
>
> If any are missing, **STOP** and instruct the user to run the prerequisite commands first.

---

## Implementation Rules

### What You MAY Read:
- `features/<feature-name>/2_tech_spec.md` — For function signatures, data models, API contracts, and architecture
- `features/<feature-name>/tests/` — To understand what the code must satisfy
- Existing source code in `backend/`, `frontend/` — To understand current patterns and integrate properly
- `features/*/3_summary.md` — To understand integration points with other features

### What You MUST NOT Do:
- Do NOT modify test files generated by `/generate-tests`
- Do NOT change function signatures defined in `2_tech_spec.md`
- Do NOT add functionality not specified in the tech spec

### Implementation Approach:
1. Read `2_tech_spec.md` to understand the required architecture and signatures
2. Read existing test files to understand what assertions must pass
3. Implement the minimum production code that satisfies all tests and contracts
4. Follow existing project conventions for file organization, naming, and patterns
5. Add appropriate error handling as specified in the edge cases

---

## Output Expectations
- All exported functions match signatures from `2_tech_spec.md` exactly
- Code is organized following the project's existing directory conventions
- All test assertions should be satisfiable by the implementation
- Include inline documentation for public APIs

---

## Post-Implementation
After implementation is complete, instruct the user to:
1. Run the test suite to verify all tests pass
2. Run `/validate-feature <feature-name>` to check pipeline completeness
3. Run `/generate-summary <feature-name>` to create the context capsule
